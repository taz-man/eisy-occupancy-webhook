## 2026-11-07T23:16:42.962137+00:00

Initial version: webhook-based replacement for the UDI Portal Occupancy / Occupancy V2 node server (going away). Devices and optional locations come from a typed-params list; each device gets an In/Out (True/False) node, each location an aggregate node (occupied if any member is in). The portal webhook endpoint has no authentication, so every call must carry a per-install secret (persist/occupancy_secret, generated on first start, rotatable with the NEWTOKEN command). Calls are generic: ?occ=<address>&tok=<secret>&st=in|out (Locative's own trigger=enter|exit is accepted when st is absent). Evidence: UD wiki Occupancy & Locative page (old behaviour), UD developer docs 'Using Webhooks' text supplied by the developer (endpoint format, no auth, polyglot.webhookStart/WEBHOOK/webhookResponse), and udi_interface 3.4.8 source (Interface.webhookStart/webhookResponse, getNodes/getNodesFromDb/delNode, Node internals). Unverified: exact keys of the data dict handed to the WEBHOOK handler (code accepts query or querystring, headers, body as dict/JSON/urlencoded string) and whether Locative appends its own query parameters to the URL it is given (our parameter names occ/tok/st were chosen to avoid its device/id/trigger fields).
